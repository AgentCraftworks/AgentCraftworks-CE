Two-minute architecture walkthrough

Step 1 of 6: Webhook arrives

1. A webhook arrives — and is verified first

~20 seconds · typescript/src/middleware/webhook-signature.ts

GitHub calls POST /api/webhook when a pull request is opened, reopened, labelled or synchronised, and on ping, installation and installation_repositories.

Before anything is parsed, CE recomputes the HMAC-SHA256 of the raw body with GH_CE_WEBHOOK_SECRET and compares it in constant time with the X-Hub-Signature-256 header. A mismatch is a 401; nothing downstream runs.

sha256=HMAC(secret, rawBody)  →  200 handled
anything else                 →  401 Invalid webhook signature

2. CODEOWNERS decides who reviews

~20 seconds · services/codeowners-router.ts, utils/codeowners.ts

For a pull request, CE fetches the changed files and the repository's CODEOWNERS (.github/CODEOWNERS, then CODEOWNERS, then docs/CODEOWNERS) and matches paths to owners. Precedence is CODEOWNERS → labels → none (@code-reviewer).

When the App is first installed on a repository without CODEOWNERS, CE opens a setup pull request proposing a default file — humans merge it; CE never does.

3. Engagement levels decide what agents may do

~25 seconds · services/action-gate.ts, services/action-classifier.ts

Each repository has a dial (default 1 — Observer). Every action is classified into a tier, and an action is permitted only when the effective level reaches the tier's requirement. Denied writes are skipped and logged; at level 2+ a single PR comment explains what was withheld.

Community Edition supports levels 1–3. Requesting level 4 or 5 on POST /api/dial/:owner/:repo returns 422 ENTERPRISE_REQUIRED (ADR-CE-001).

4. Work moves through a four-state handoff machine

~20 seconds · utils/handoff-state-machine.ts, services/handoff-service.ts

A handoff is the unit of work passed from one agent (or human) to another. It is a UUID with a state, a history of transitions and optional schema-validated context (code-review, security-finding, test-result).

failed always carries a reason prefix — rejected:, abandoned:, error: or timeout:. Overdue is computed, never stored. State lives in memory and resets when the process restarts.

5. Agents drive the same machine over MCP

~20 seconds · mcp/server.ts, .mcp.json

The MCP server is a stdio process (npm run mcp) that GitHub Copilot, Claude and other MCP clients launch from .mcp.json. It exposes exactly six tools — the protocol contract that Enterprise is compatible with.

create_handoff      accept_handoff      complete_handoff
query_workflow_state attach_context      get_context

6. What ships in Community Edition

~15 seconds · docs/EDITIONS.md

  • Webhook server with HMAC-SHA256 verification and per-IP rate limiting
  • CODEOWNERS routing with label fallback, and the setup pull request
  • Engagement levels 1–3 with the action gate and REST dial API
  • Four-state handoff machine with schema-validated context
  • Six-tool MCP server over stdio
  • In-memory storage — single replica, state resets on restart
  • Docker Compose for local runs; Azure Container Apps via azd

CE is the MIT-licensed protocol layer — the handoff FSM, the engagement-level model and the six-tool MCP subset that Enterprise is compatible with.

CE isn't the core Enterprise is built on, nor a stripped-down Enterprise. Levels 4–5, durable multi-replica storage and the full tool catalogue are Enterprise features.
